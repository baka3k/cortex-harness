# MCP FalkorDB Search and Expansion Hardening — 2026-07-19

## Context

Unified MCP advertised FalkorDB as the normal runtime, but several search paths still behaved as if Neo4j were the implicit backend. `explore_graph` could inherit an empty provider, a Bolt URI, and database `neo4j`; direct workflow/bridge tools opened a raw Neo4j driver; and the servlet freshness predicate generated a Neo4j-only `EXISTS` subquery unless provider variables were present. At the same time, parser aliases and named framework profiles narrowed the searchable schema enough to omit canonical language symbols, aliases, templates, and core relationships during graph expansion. The work follows the [parser/MCP runtime alignment plan](../../plans/260719-2150-parser-mcp-runtime-alignment/plan.md) and extends the earlier [MCP query capability hardening plan](../../plans/260719-0100-mcp-query-capability-hardening/plan.md).

## Impact

FalkorDB is now the actual default across explore, expansion, bridge, and workflow paths instead of only the advertised default. Parser aliases and framework overlays retain the underlying language graph, while expanded results contain enough seed and symbol metadata for an MCP client to explain why each neighbor was returned. Provider diagnostics also make partial/degraded retrieval observable. **Risk level: medium** because the change touches shared routing and Cypher traversal, but it is additive or compatibility-preserving and is covered by focused unit tests plus live Falkor execution.

The active index remains a separate completeness constraint. A read-only `scripts/validate_retrieval.py` check reported `ok=false` for project/graph `cortext`: 4,138 vector points, 5,115 graph nodes, 3,873 linked symbols, 265 missing graph IDs, 790 location mismatches, 381 modules, and 5,057 expandable seeds. Its indexed commit is `e1ca65f394d7ceae364272a47a9985073cd8a2cb`, behind current HEAD `44c453b44fcb5b51de2712a8ee6fd2eddc2e47ab`. MCP can now return the available graph facts correctly, but a full project resync is still required before callers can expect complete up-to-date coverage.

The repository-wide run executed 282 tests with 25 failures, 13 errors, and 8 skips. The failing groups were outside this MCP hardening scope and included absent fixture `tests/fixtures/flutter-protocol-v1.jsonl`, existing COBOL/ASP.NET/Flutter fixture/runtime failures, and incremental-worktree assumptions; the focused MCP suites above remained green.

## Decision

Use one shared provider-neutral driver contract and make FalkorDB the explicit source default, while retaining Neo4j only when the caller deliberately selects it. Compute hop distance and seed provenance in Cypher rather than reconstructing approximate distances in Python, because the graph engine already owns the traversed paths and can deduplicate neighbors consistently. Preserve canonical language symbols underneath framework aliases instead of treating a framework as a replacement schema. Return structured degradation diagnostics rather than silently collapsing connection failures into empty search results.

Index repair was intentionally kept separate from the MCP code update: resyncing is write-heavy operational work, and changing query behavior cannot manufacture graph facts that are missing or stale.
