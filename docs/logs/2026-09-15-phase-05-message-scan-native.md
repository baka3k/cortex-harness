# Phase 05 — Message-scan native port (Rust) — 2026-09-15

## Context
Red-team Critical #2 from `plans/260915-analyzer-layer-rust-cutover/`: message-scan
plane (graph `MessageEndpoint` merges + message qdrant vectors) only existed in
Python children (`code-tiny/tools/common/message_scan.py` 860 LOC +
`message_detectors/` 856 LOC across 17 detector files). Rust children
accept-and-ignored `--enable-message-scan` / `--message-*`. With 17 parsers
message-enabled under the default `--sync-mode both`, flipping default to Rust
without porting would silently kill this capability.

## Change
Port the message-scan plane into `rust/crates/cortex-sync/src/message_scan/`:
- `detectors.rs` — 17 language detectors + `GenericMessageDetector` + base
  helpers (`unquote`, `looks_endpoint`, `truncate_chars`, `collapse_whitespace`).
  Each detector byte-exact semantics for `extract_sender` regex and
  `extract_fields` precedence (`sendmessage/postmessage` → `registerreceiver` →
  `startactivity/startservice` → broadcast-class → `looks_endpoint`).
  UTF-8-safe char-truncation via `chars().take(n).collect()` (NOT byte slicing).
- `record.rs` — `MessageRecord` + `stable_message_id` (sha1[:24] over 7-tuple
  with `msg::` prefix) + `hash_vector` (sha1 token bucketing, L2 normalize).
- `collect.rs` — `collect_messages_for_parser` with file walker (skip
  VCS/target/node_modules), `split_args` depth/quote-aware state machine,
  per-line sender mapping, confidence scoring (0.55 + 0.2 + 0.1 + 0.1 cap 0.99).
- `artifact.rs` — `write_message_artifact` atomic JSON (`.tmp` rename), schema
  matches Python (schema_version, source{file,line}, confidence, language).
- `extensions.rs` — parser → file-extension map mirroring Python
  `_PARSER_EXTENSIONS`.
- `mod.rs` — public API + `safe_segment` (run-fold semantics matching Python
  `re.sub`), `parser_from_language` aliases, `default_message_collection_name`.
- `lib.rs` — public library surface so integration tests can import
  `cortex_sync::message_scan` and downstream `cortex-embed` can re-use the
  graph/qdrant upsert primitives in phase-06.

Orchestrator integration at `rust/crates/cortex-sync/src/orchestrator.rs:2640`
adds `run_native_message_scan_lane` running after primary parser phase:
iterates `registry::message_enabled_parsers()`, collects messages per parser
(incremental: only changed/deleted files), writes per-parser artifact, surfaces
`summary["native_message_scan"]` with explicit `deferred-phase-06` markers for
graph + vector upsert (ownership handoff).

Tests:
- 27 unit tests (mod-level: detectors/record/collect/artifact/extensions).
- 4 integration tests at `rust/crates/cortex-sync/tests/message_scan_parity.rs`
  including fixture-based parity against Python baseline.
- `rust/tests/fixtures/message_scan/expected_records.json` — golden generated
  by Python `tools.common.message_scan.collect_messages_for_parser`
  (cross-validated: 17/17 records match byte-for-byte).

## Impact
- **Who/what:** Rust children no longer need to accept-and-ignore
  `--message-*` (the `--enable-message-scan` flag has meaning again); orchestrator
  can flip default to Rust without losing message-scan capability.
- **Risk level:** **med** — graph upsert + Qdrant vector lane deferred to
  phase-06 (cortex-embed component gates). Until phase-06 lands, the Python
  children continue writing graph MessageEndpoint nodes / message vectors
  during the embedding pass via `force_python=true`. Phase-08 retired-error
  closes the Python path post-dogfood.
- **Downstream:** phase-06 (cortex-embed) reuses the `MessageRecord` struct
  + artifact JSON; phase-07 composition gate reruns the parity test on a
  wider synthetic corpus; phase-08 retired-errors Python message-scan lane.

## Decision
- **Cross-parser plane in cortex-sync, not per-analyzer.** Mirrors Python:
  message-scan reads source files independent of any specific parser's artifact,
  so it belongs at orchestrator level. Avoids 17× duplication of detector
  registries per Rust analyzer binary.
- **Parity test cross-validates against Python baseline, not Rust output.**
  First review found the parity test was bootstrapping from Rust itself
  (any Rust regression passed silently). Now `expected_records.json` is
  generated by Python `collect_messages_for_parser` and committed; the test
  asserts Rust output matches Python output exactly.
- **Char-based slicing everywhere.** Python `s[:n]` slices by character;
  Rust `String::truncate(n)` slices by byte (UTF-8 panic on multi-byte char
  boundary). All detectors now use `truncate_chars(value, n)` =
  `value.chars().take(n).collect()`.
- **Sender `re.sub(r"\s+", " ")` collapse for GenericMessageDetector.**
  Python collapses whitespace runs in the unquoted message_name before
  truncating; Rust port now mirrors via `collapse_whitespace` helper.
