## A. Doctor infrastructure (drift-report home)

- **Doctor exists in `scripts/mcp-lifecycle.py`**, not dev.py. Dispatch: `ACTIONS = {... "doctor": invoke_doctor ...}` at `scripts/mcp-lifecycle.py:2010`; `invoke_doctor()` at `:1359` orchestrates.

Output shape: one line per check, `[doctor][ok]  name - message` / `[doctor][fail]` (required, counts toward failures) / `[doctor][warn]` (`required=False`, report-only, does not fail). `invoke_doctor` sums failures and raises `RuntimeError("Doctor found N required check(s) failing.")` at `:1486-1487`.

- **Registry scan already lives here**: `_scan_project_backends(config_dir)` at `scripts/mcp-lifecycle.py:442` parses `.cortext-harness/config/*.json`, classifies `backend_mode`, and **silently skips malformed JSON** (docstring `:447-449`) — exactly the "malformed config JSON" signal the drift report wants (currently swallowed).
- CLI home: `dev doctor` is a thin delegator — `cortex_harness/dev.py:2793-2796` `@cli.command() def doctor(): _run_lifecycle("doctor")`; `_run_lifecycle` at `:2590-2640` runs the script as a subprocess with `cwd=caller_directory` for `doctor`/`start` (so registry discovery walks from the user's project root). `Makefile:66-67` `make doctor` → same. - **Windows wrinkle**: on win32 `_run_lifecycle` runs the PowerShell twin `scripts/mcp-lifecycle.ps1` instead (`cortex_harness/dev.py:2597-2606`); that file has its own parallel doctor (`Write-DoctorCheck` at `scripts/mcp-lifecycle.ps1:537`). - **Verdict (evidence-based)**: `scripts/mcp-lifecycle.py::invoke_doctor` is the natural home — registry parsing, storage resolution (`_resolved_storage` `:943`), warn-style checks, and existing tests (`tests/test_doctor_remote.py` imports the lifecycle module via importlib from `scripts/mcp-lifecycle.py:15,30` and mocks `doctor_check`) are all there. dev.py has no storage/registry inspection logic of its own.

## E. Response envelope conventions

- Envelope: `{ok, data, error}` in `structuredContent`; `content` is a one-line summary; `_meta` carries `{contract, contractVersion, tool}`. Canonical impl `cortex_harness/mcp_contract.py`: `normalize_success` `:51-54` (`{"ok": True, "data": data, "error": None}`), `normalize_error` `:168-220`, `result_meta` `:223-230`, `result_summary` `:233-259`. Spec: `docs/mcp-output-contract.md:21-190` (musts), error-code table `:177-188`.
- Applied to mind tools by `_standard_tool` wrapper: `doc-tiny/mcp_graph_rag.py:762-814` — catches exception → `normalize_error(exc)`, else `normalize_success(data)`; strips the `return` annotation and re-exposes the original signature (`:804-811`) so fastmcp derives inputSchema from the business signature.
- **Where `scope`/`warnings` sit**: inside `data` (business payload). Evidence: "Tên field nghiệp vụ MAY khác giữa các tool; envelope không được khác" (`docs/mcp-output-contract.md:81-84`); "`db`, `collection` hoặc `collections_searched` phải phản ánh target thực tế" (`:285` — collections_searched already contractually required to reflect actual targets). Precedent for a `warnings` list inside a diagnostics block: `code-tiny/mcp/unified_mcp.py:647-680`. Caution: `test_missing_paragraph_is_an_empty_success_without_warning_shape` (`tests/test_unified_contract_doc_paths.py:215-235`) asserts a *not-found* case stays a plain success — warnings must be additive fields, not a new top-level shape; and "Không trả warning thay cho error nếu request không thể thực hiện" (`docs/mcp-output-contract.md:169`).
- Error codes relevant to `strict_scope`: `LookupError` → `collection_unavailable`; `ProjectNotRegisteredError` → `project_not_registered` (`cortex_harness/mcp_contract.py:21,57-68`; table row `project_not_registered` at `docs/mcp-output-contract.md:183`). Note `ProjectNotRegisteredError` subclasses `KeyError` (hence `LookupError`), but `_exception_code` maps by class **name**, so raising the registry error yields `project_not_registered`, not `collection_unavailable`.
- Note: `semantic_search`/`semantic_graph_search` already return `collection` + `collections_searched` (`doc-tiny/mcp_graph_rag.py:954-955,1104-1105`), but those are the *requested/resolved* names from `_resolve_doc_collections`, **not** the actually-present collections each store was probed for — the real probe loop computes `present` internally and discards it (`:419-429`). A truthful `scope.per_collection_hits` must be returned from `qdrant_search_entity_payload` (`:358-488`), which currently returns only merged rows.

## Risks / open questions

- **Live config uses a key nobody reads** (`doc.env.QDRANT_COLLECTION_DOC` in `.cortext-harness/config/dev.json`). Dual-key compat must pick a precedence (`QDRANT_COLLECTION` then `QDRANT_COLLECTION_DOC`, or vice versa); the registry doc (`docs/PROJECT_REGISTRY.md:128-129`) still documents only `QDRANT_COLLECTION`.
- Doc-side delegation to the code registry changes error identity: `doc_local_qdrant.py:67-75` already re-wraps the code-side `ProjectNotRegisteredError` into the doc-side class because they are *same-named, unrelated* KeyError siblings (`doc-tiny/mcp_graph_rag.py:43-63`); after unification the dual-catch tuple `_PROJECT_RESOLVE_ERRORS` and the re-export shim become dead but many tests patch `doc-tiny/project_contract` symbols directly (e.g. `tests/test_unified_contract_doc_paths.py:105,265,582`; `doc-tiny/tests/test_mcp_project_id_optional.py:170-171`) — a facade re-export in `project_contract.py` (keep the names, delegate the bodies) is the low-blast-radius shape.
- Fan-out cap choice (12): no existing constant or precedent found (`unknown` — closest is code-side parser fan-out capped at `len(BACKENDS)`, `docs/UNIFIED_INGEST_QUERY_CONTRACT.md:120-124`). Empty-graph discovery can't distinguish "junk" from "legitimately empty" via GRAPH.LIST alone (it lists names, not emptiness) — emptiness checks would need a query, which materializes graphs; the drift report may have to accept name-level existence only for FalkorDB, while Qdrant can check `count`/`get_collection_info`.
- Windows: doctor drift report added only to `mcp-lifecycle.py` won't run under `dev doctor` on win32 (`dev.py:2597-2606` dispatches to `mcp-lifecycle.ps1`).
- Dead code spotted: unreachable duplicate `return collections or [QDRANT_COLLECTION]` at `doc-tiny/mcp_graph_rag.py:296-297` (leftover after `:288-293`); safe to remove in the same change.
- `scope.collections_searched` today means *requested* names (`mcp_graph_rag.py:954-955,1104-1105`); renaming/repurposing it as actually-searched is a client-visible field-semantics change (`docs/mcp-output-contract.md:341` "Không đổi kiểu/ý nghĩa field hiện hữu âm thầm") — prefer additive `scope.per_collection_hits` and leave the old field as-is.
- `_qdrant_stores` / `_graph_drivers` are process-lifetime caches keyed by raw project_id (`doc-tiny/mcp_graph_rag.py:110-111`); existence-gating changes don't invalidate them — a shard created after a negative probe stays invisible until restart (`inferred` from cache usage `:144-154,180-207`; no TTL found).

## Recommended approaches (max 3)

1. **Facade delegation, not deletion**: keep `doc-tiny/project_contract.py` exporting the same names (`resolve_doc_candidates`, `resolve_project_targets`, `ProjectTargets`, error classes) but implement them by delegating to `tools.common.project_registry` under the existing `try/ImportError` guard pattern (`doc_local_qdrant.py:55-65` precedent), reading both `QDRANT_COLLECTION` and `QDRANT_COLLECTION_DOC` doc-env keys inside the code-side `_doc_qdrant()`.
