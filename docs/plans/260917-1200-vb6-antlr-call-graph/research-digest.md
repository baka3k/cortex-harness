**F1.3 — API entry points.**
`io.proleap.vb6.asg.runner.VbParserRunner` (interface, `src/main/java/io/proleap/vb6/asg/runner/VbParserRunner.java`):
```java
Program analyzeCode(String vbCode, String moduleName, VbParserParams params)
Program analyzeFile(File vbFile [, VbParserParams params])
Program analyzeFiles(List<File> vbFiles [, VbParserParams params])   // whole-program ASG
```
`analyzeFiles` parses every file into ONE `Program`, then runs multi-pass analysis (type definitions → declarations → expressions → type assignments ×4, `VbParserRunnerImpl.analyze()`). This is the cross-module resolution entry point — call it once per batch, not once per file. Multi-pass detail matters for worker cost model: per-batch JVM startup amortizes like the Roslyn worker's single `dotnet` invocation.

**F1.4 — Module structure and procedures.**
- `Program.getModules()` / `getClazzModules()` / `getStandardModules()` / `getModule(name)` / `getClazzModule(name)` (`asg/metamodel/Program.java`).
- `Module` (`asg/metamodel/Module.java`): `getSubs()`, `getFunctions()`, `getPropertyGets/Lets/Sets()`, `getProcedures()`, `getSub(name)`, `getFunction(name)`, plus `getVariables()`, `getConstants()`, `getEnumerations()`, `getAttributes()`, `getLines()` (raw source lines), `getTokens()` (CommonTokenStream), `getVersion()`, `isModuleWithMetaData()`.
- `Procedure extends Scope, Declaration, Statement, VisibilityElement` (`asg/metamodel/Procedure.java`): `getArgs()`, `getArgsList()`, `getCalls()`, `hasReturnType()`, visibility via VisibilityElement (Public/Private/Friend — exact enum members not enumerated here **[unverified: enum member list]**).

**F1.5 — Call sites incl. implicit/no-paren calls (the core need).**
- ASG metamodel has a dedicated `call` package: `Call` interface exposes `getCallType()` returning `CallType` enum with exactly: `SUB_CALL, FUNCTION_CALL, PROPERTY_GET_CALL, PROPERTY_LET_CALL, PROPERTY_SET_CALL, VARIABLE_CALL, ARRAY_ELEMENT_CALL, CONSTANT_CALL, DICTIONARY_CALL, MODULE_CALL, MEMBERS_CALL, ME_CALL, ELEMENT_VARIABLE_CALL, API_PROCEDURE_CALL, API_PROPERTY_CALL, ENUMERATION_CALL, ENUMERATION_CONSTANT_CALL, API_ENUMERATION_CALL, API_ENUMERATION_CONSTANT_CALL, TYPE_ELEMENT_CALL, RETURN_VALUE_CALL, ARG_CALL, UNDEFINED_CALL` (`asg/metamodel/call/Call.java`).
- Resolved accessors: `SubCall.getSub()`, `FunctionCall.getFunction()` return the target ASG `Sub`/`Function` (`call/SubCall.java`, `call/FunctionCall.java`). `UNDEFINED_CALL` covers unresolved names — natural source for POSSIBLE_CALLS/late-bound lanes.
- `Procedure.getCalls()` returns `List<Call>` observed inside that procedure (`asg/metamodel/Procedure.java`) — caller-side collection is direct.
- The grammar/Scope layer has explicit hooks for implicit calls: `Scope.addCall(CallContext, ImplicitCallStmt_InStmtContext)`, `addCall(..., ICS_S_VariableOrProcedureCallContext)`, `ICS_S_MembersCallContext`, `ICS_S_ProcedureOrArrayCallContext`, `ICS_B_ProcedureCallContext`, `ICS_B_MemberProcedureCallContext`, `ECS_ProcedureCallContext`, `ECS_MemberProcedureCallContext`, `ExplicitCallStmtContext` (`asg/metamodel/Scope.java` import list + addCall overloads). I.e. no-paren Sub calls, `Call Foo x` explicit calls, With-block member calls, and dictionary `!field` calls are all first-class grammar constructs. This directly addresses the regex misses catalogued as E3 in the prediction report.
- Line numbers: every ASG element exposes the ANTLR parse-tree node — `ASGElement.getCtx()` returns `org.antlr.v4.runtime.ParserRuleContext` (`asg/metamodel/ASGElement.java`) → `ctx.getStart().getLine()` (1-based) for calls, procedures, and modules. `Module.getLines()` additionally stores the split source lines.
- Visitor escape hatch for anything the ASG misses: extend `VisualBasic6BaseVisitor<Boolean>` and map contexts to ASG via `program.getASGElementRegistry().getASGElement(ctx)` (README "complex" example).

**F1.6 — File-type handling (.bas/.cls/.frm/.ctl) (CRITICAL LIMITATION + workaround).**
- `VbParserRunnerImpl.isClazzModule()` → extension `cls`; `isStandardModule()` → extension `bas` (source verified). `VbModuleVisitorImpl.visitModule()` creates `ClazzModuleImpl` for cls, `StandardModuleImpl` for bas, **and `null` for anything else** (`asg/visitor/impl/VbModuleVisitorImpl.java`, visitModule body: `} else { result = null; }`). So `.frm`/`.ctl`/`.dsr` files produce **no ASG module at all** — form/class procedures and calls inside them silently vanish from the ASG. Open issue #20 "ASG only available for BAS/CLS?" (no maintainer reply) confirms this is unresolved upstream.
- The grammar itself DOES parse `.frm` content including the designer metadata block: test resource `src/test/resources/io/proleap/vb6/ast/frm/Form1.frm` (VERSION 5.00 header, `Object = "{GUID}#1.1#0"; "TABCTL32.OCX"`, nested `Begin VB.Form ... End` block, then `Attribute VB_Name = "Form1"` etc.) is parsed by `Form1Test` via the AST test runner (`src/test/java/io/proleap/vb6/ast/frm/Form1Test.java`). Test-resource extension census: 181 `.cls`, 15 `.bas`, 1 `.frm`.
- **Workaround (evidence-backed):** materialize each `.frm`/`.ctl` as a temp `.cls` file (verbatim bytes or via a temp copy) and feed those paths to `analyzeFiles`. The module will then be a `ClazzModule` whose name comes from `Attribute VB_Name` (see F1.7), and the designer block parses as grammar metadata. This is the same "pre-filter designer metadata" lever the prediction report already identified (A5) but with the stronger property that the grammar tolerates the block without stripping. `.dsr` files with GUID-form `Begin {GUID} name` headers still throw `VbParserException: syntax error` — open issue #21 (an .dsr-only concern; not in the VB6 analyzer's file set today **[vb6 file extensions actually scanned: see `_scan_vb_files` — not re-verified line-by-line this session]**).
- Module name resolution: `VbParserRunnerImpl.analyzeDeclaredModuleName` extracts `Attribute VB_Name` and it **overrides** the capitalized filename stem (`getModuleName` = `capitalize(FilenameUtils.removeExtension(...))`) — verified in source; README states the same.

**F1.7 — Known limitations (GitHub issues, uwol/proleap-vb6-parser).**

- #18 (closed): no Maven repo deployment (see F1.1).
- #5 (closed, residual): `#If/#Else/#Const` precompiler directives require external preprocessing — the parser copes only when each branch is independently valid VB6. Maintainer recommends a preprocessor pass (as done in his cobol85parser). - #4 (closed after multiple rounds): historical bugs in member-call resolution inside WITH statements, control properties, arrays, cross-class member name clashes — all fixed with regression tests, but the history shows this resolution area had real defects; keep golden fixtures for WITH/arrays/Me cases.

**F1.8 — Robustness knobs.**
`VbParserParams` exposes `getIgnoreSyntaxErrors()` and `getCharset()` (used in `VbParserRunnerImpl.parseCode` to optionally install a `ThrowingErrorListener`). Default values not verified **[unverified]**; the worker should set `ignoreSyntaxErrors=true` for best-effort parse or catch `VbParserException` per file to drive per-file regex fallback — either way, surface `parse_meta.has_error` per file as the Roslyn worker does.

**F1.9 — Fallback path: grammars-v4 vendoring.**
`antlr/grammars-v4/vb6` contains `VisualBasic6Lexer.g4` (5,387 B), `VisualBasic6Parser.g4` (21,813 B), `desc.xml`, `pom.xml`, `readme.md`, `examples/` (directory listing via GitHub API, 2026-09-17). ### R2 — Roslyn worker contract (in-repo pattern to mirror)

**F2.1 — Adapter: `code-tiny/tools/vb/vb_roslyn_adapter.py` (whole file, 219 lines).**
- Build locking: module-level `_BUILD_LOCK = threading.Lock()` + `_BUILD_CACHE: Dict[str, str]` (lines 11-12); `_ensure_worker_built` (80-106) builds once per project path with `dotnet build <csproj> -c Release`, raises `RuntimeError` with last 50 output lines on failure, caches the resolved dll path keyed by csproj.
- Runtime selection: `_worker_dll_path` (24-48) prefers `bin/Release/net9.0/<Name>.dll` then net8.0, then any `net*` TFM dir (newest first), filtered by `_installed_dotnet_runtime_majors()` which parses `dotnet --list-runtimes` (56-77). A VB6/Java mirror: resolve a jar under `target/` and check `java -version` compatibility.
- Invocation protocol (109-178): writes a temp JSON manifest `{"files": [relpath, ...]}` (delete=False, removed in `finally` 213-218); then `subprocess.run(["dotnet", dll, "--root", root_abs, "--files-manifest", manifest, "--semantic", mode, "--workspace-timeout-ms", N, "--file-timeout-ms", N, "--parse-cache-version", V], timeout=timeout_sec)` — **argv flags, not stdin; stdout is the entire JSON result**. Timeouts: subprocess-level `timeout_sec` (default 600 s, min clamp 1.0), workspace 120,000 ms and file 60,000 ms (min clamp 5,000 ms each).
- Error semantics: non-zero returncode → `RuntimeError` with last 80 lines of stderr/stdout (180-186); stdout not parseable as JSON → `RuntimeError` with 2,000-char snippet (188-192).
- Result split (194-212): for each `results[]` item: `ok=true` + dict `payload` → `success[relpath]`; otherwise `errors[relpath] = error string`. Worker meta keys: `workspace_kind`, `solution_or_project_path`, `semantic_enabled`, `semantic_errors`.

**F2.2 — Worker: `code-tiny/tools/vb/roslyn_worker/Program.cs` (1,076 lines) + `RoslynVbWorker.csproj`.**
- CLI: `--root <path> (--file <path> | --files-manifest <path>) [--semantic off|auto|on] [--workspace-timeout-ms N] [--file-timeout-ms N] [--parse-cache-version V]` (usage string, Program.cs:187). Exit codes: 0 success, 1 fatal (stderr line `[roslyn-worker] fatal: ...`, 109-113), 2 usage error.
- Manifest loading accepts JSON object `{"files":[...]}`, JSON array, or newline list (222-269) — the Python side sends the object form.
- Per-file semantics: `foreach` over files with `CancellationTokenSource(FileTimeoutMs)`; `OperationCanceledException` → `ok=false, error="timeout after {n}ms"`; any other `Exception` → `ok=false, error=ex.Message`; success → `ok=true, payload=<dict>` (63-97). One bad file never aborts the batch.
- Per-file payload shape (794-823): `functions`, `calls`, `classes`, `namespaces`, `relations` (always `[]`), `properties`, `events`, `interfaces`, `enums`, `constants`, `variables`, `file_def` (with `imports`/`exports`), `parse_meta`, `parse_cache_version`.
- Call rows (571-580): `{caller_id, caller_scope, callee_name, callee_id (nullable), callee_arity (nullable int), call_line}` — callee_id filled only when semantic resolution succeeded; otherwise left null (regex-side resolver handles it).
- Function symbol_id scheme: `{namespace}.{type}.{name}/{arity}@{relPath}` (864-868) — the `@relPath` suffix is what VB6 Class defs lack today (prediction report E7).
- `parse_meta` (776-792): `parser_language, parse_cache_version, has_error, error_nodes, line_count, parser_engine, semantic_mode, semantic_enabled, fallback_reason, worker_elapsed_ms, workspace_kind, solution_or_project_path, semantic_errors, resolution_source`.
- csproj: `net8.0;net9.0` multi-target, packages Microsoft.Build.Locator 1.9.1, Microsoft.CodeAnalysis.VisualBasic 4.11.0, Workspaces.MSBuild 4.11.0 (RoslynVbWorker.csproj:4-11).

**F2.3 — Python-side integration: `code-tiny/tools/vb/vb_analyzer_base.py`.**
- Engine cascade: `engine_for_run = "regex" if vbnet_parser_engine == "regex" else "roslyn"` (line 578); `if dialect == "vbnet" and vbnet_parser_engine != "regex": payloads = await _parse_vbnet_with_roslyn_batch(...)` (585-599); else `_parse_files_parallel` regex path (600-609). A VB6 mirror adds `dialect == "vb6"` branch + `--vb6-parser-engine auto|antlr|regex` (current CLI only has `--vbnet-parser-engine`, 1088-1093; `vb6_analyzer.py:18` just forwards `--dialect vb6`).
- `_parse_vbnet_with_roslyn_batch` (368-508): parse-cache lookup first (keyed `file_signature` + `PARSE_CACHE_VERSION`, 387-395); the **miss list** is sent to the worker in one batch; per-file fallback to `parse_vb_file(..., vbnet_parser_engine="regex", fallback_reason=...)` when payload missing/invalid shape or batch raised (425-459); `_is_valid_payload_shape` requires keys `functions, calls, classes, file_def, parse_meta` (361-365); `_ensure_parse_meta_defaults` stamps `parser_engine, requested_engine, semantic_mode, fallback_reason, resolution_source...` (327-358); results written back to parse cache (499-500).
- Batch protocol detail worth mirroring exactly: worker receives only cache misses; cache hits never re-enter the worker.
- Graph write of calls today (748-754): `for call in payload["calls"]: if call.callee_id: calls_rows.append({caller_id, callee_id, call_type:"call_expression"})` — unresolved calls silently dropped (prediction report E5 confirmed), and rows carry no line/arity/resolution props.

### R5 — VB6 semantics checklist for the resolver

**F5.1 — .vbp structure.** INI-like; key entries: `Type=Exe` (project type), `Form=frmMain.frm`, `Module=modUtils; modUtils.bas` (module-name; filename), `Class=clsCustomer; clsCustomer.cls`, `Object={GUID}#maj.min#0#path#control` (ActiveX controls from Project→Components), `Reference=*\G{GUID}#maj.min#0#path#description` (COM type libraries from Project→References). Sources: Stack Overflow [Reference vs Object lines](https://stackoverflow.com/questions/24084886/differences-between-reference-and-object-lines-in-a-vbp), [VBP reference line format](https://stackoverflow.com/questions/28902971/format-of-a-vbp-file-reference-line), [Software Saved build notes](https://softwaresaved.github.io/distance-consultancy/develop/BuildVisualBasic.html). The `Module=`/`Class=` first field is the module name (should agree with `Attribute VB_Name` inside the file). A VB6 project model can be built from either source; `Attribute VB_Name` is authoritative for call qualification.

**F5.2 — Attribute VB_Name.** Module name used by callers to qualify (`modUtils.DoThing`), may deviate from filename; ProLeap prefers it over the filename stem (F1.6). Every .bas/.cls/.frm code section starts with `Attribute VB_Name = "..."`; .frm additionally has VB_GlobalNameSpace/VB_Creatable/VB_PredeclaredId/VB_Exposed (see Form1.frm, F1.6).

**F5.3 — Visibility and unqualified call resolution.** Procedures in standard modules are Public by default; Public .bas procedures are callable project-wide and unqualified from any module; Private procedures resolve only within their module; two same-named Public procedures in different .bas modules cause "Ambiguous name detected" and require module qualification. Form/class module procedures default to Public too but must be qualified (instance or class name) from outside the module. Sources: SO [default of procedure public or private](https://stackoverflow.com/questions/4464246/vb-default-of-procedure-and-module-public-or-private), VBForums [ambiguous private functions across modules](https://www.vbforums.com/showthread.php?736779), Microsoft Learn [scope and visibility](https://learn.microsoft.com/en-us/office/vba/language/concepts/getting-started/understanding-scope-and-visibility) (VBA doc, same rules). Practical resolution order for an unqualified name **[inferred — no single canonical doc found in timebox]**: local variables/params → enclosing procedure/module members (incl. form-module members) → project-public standard-module procedures; on multiple public matches → ambiguous. VB6 names are case-insensitive (ProLeap normalizes; vb_common resolver lowercases today).

**F5.4 — Form default instances.** Each form class has a hidden auto-instantiated global instance named after the form: `Form1.Show`, `Load frmMain`, and `frmMain.PublicSub` all reference it (touching it loads the form). Sources: InformIT [Programming without default form instances](https://www.informit.com/articles/article.aspx?p=102148&seqNum=6), SO [referencing the class name of a form](https://stackoverflow.com/questions/79118023/vb6-referencing-the-class-name-of-a-form-instead-of-an-object-variable), VBForums [referencing a public sub on a loaded form](https://www.vbforums.com/showthread.php?876955). Resolver consequence: `FormName.Proc` binds to the form class module's Public procedures; .frm ASG registration (F1.6 workaround) is a prerequisite for this binding. `Attribute VB_PredeclaredId = True` marks predeclared classes similarly.

**F5.5 — Implements-based dispatch.** A class may `Implements IFoo` and calls through an `As IFoo` variable dispatch to the implementing class's `Private Sub IFoo_Method` at runtime — statically, the callee set is the set of implementers. Source: [VB6 vs VB.NET white paper](https://www.vbmigration.com/white-papers/vb6-vs-vb-net-language/) (covers Me, enum members as global names, scoping). ProLeap has `integration/overrides` test resources suggesting override handling exists **[depth of ProLeap Implements resolution unverified]**.

**F5.6 — Late binding.** `Dim o As Object` / `CreateObject(...)` member calls cannot be resolved statically; must be recorded as POSSIBLE_CALLS with an explicit late-bound status (prediction report §5 already assigns `resolution_status:"late_bound"`).

**F5.7 — With-block and dictionary idioms.** `With x ... .Method` member calls and `dict!key` dictionary calls are grammar-level constructs in ProLeap (ICS_S_MembersCall, ICS_S_DictionaryCall — F1.5); resolver needs the With-target type for member binding (ProLeap's type-assignment passes attempt this; historical bugs catalogued in issue #4).

## Conventions to follow

1. **Worker contract (mirror `vb_roslyn_adapter.py` exactly):** module-level build lock + build cache; build worker artifact from source on demand (`mvn -q -package` instead of `dotnet build`); argv-flag CLI with `--root/--files-manifest/--file-timeout-ms/--parse-cache-version` (+ Java-specific `--java-executable`/`--jar` **[new, mirrors `--vbnet-roslyn-worker-project`]**); temp JSON manifest `{"files":[relpaths]}`; single JSON doc on stdout `{workspace-ish meta..., results:[{file_path, ok, payload|error}]}`; per-file timeout → `ok=false, error="timeout after {n}ms"`; nonzero exit → RuntimeError with output tail; exit code 2 = usage, 1 = fatal.
2. **Python-side cascade (mirror `vb_analyzer_base.py:578-609, 368-508`):** send only parse-cache misses to the worker in ONE batch; per-file regex fallback with `fallback_reason` stamped into `parse_meta`; `_is_valid_payload_shape`-equivalent guard; write results back to parse cache; new CLI `--vb6-parser-engine auto|antlr|regex` beside `--vbnet-parser-engine` (1088-1093).
3. **Payload shape (mirror Program.cs:794-823):** same keys (`functions, calls, classes, namespaces, relations, properties, events, interfaces, enums, constants, variables, file_def, parse_meta, parse_cache_version`); function symbol_id must include `@rel_path` (and class ids too — fixes E7); call rows carry `caller_id, caller_scope, callee_name, callee_id?, callee_arity?, call_line`; `parse_meta.parser_engine="antlr"`, `requested_engine`, `fallback_reason`, `resolution_source`.
4. **Evidence plane:** resolved-by-ASG calls → `calls_rows` (existing write_calls path) is allowed, but any name-heuristic/ambiguous/late-bound/unresolved call MUST be published as POSSIBLE_CALLS with props `{line, arity, resolution_status}` — choose the Go route (`relations` rows through `write_relations_typed`, F3.1/F3.3) for minimal change, or the cplus route (`write_possible_calls_with_site` with stable `site_id`, F3.2) for per-callsite dedup. Never claim `resolution_class: direct_resolved` (ProLeap is not in `SEMANTIC_PROVIDERS`; enforcement fails closed, F3.3). No schema change needed (F3.4).
5. **Tests/benchmarks:** `tests/test_vb6_*.py` with unittest + code-tiny sys.path bootstrap; `tests/fixtures/vb6-application/` incl. a .vbp, .bas, .cls, .frm (with designer header), Implements pair, no-paren calls, `_` continuations, `#If` block, late-bound calls; `expected.json` golden file with per-callsite classes; `tests/benchmark_vb6_parse_quality.py` manifest-driven with latency percentiles + resolution-rate gate.
6. **Cache discipline:** bump `PARSE_CACHE_VERSION` (`vb_common.py:11`, currently `vb-family-v2026-04-03-2`) in the same PR that changes extraction; plan re-sync of already-ingested VB6 projects.
7. **ProLeap vendoring:** pin the git commit; vendor source in-repo (or submodule) and build with Maven; do not assume any remote repository has the artifact (F1.1); MIT license permits vendoring with attribution.

## Risks / open questions

- **[Critical, external]** ProLeap is not on Maven Central (F1.1) — prediction report A2 is wrong; build-from-source is mandatory and adds first-run Maven latency (mitigated by the build cache, same as dotnet worker).
- **[Critical, external]** `.frm`/`.ctl` get NO ASG module in ProLeap (F1.6, issue #20 open). The temp-copy-to-`.cls` workaround is evidence-backed (grammar parses the designer block; name comes from VB_Name) but is **[inferred]** as a integration strategy — must be proven on the fixture corpus in the spike. `.dsr` GUID Begin blocks still throw (issue #21) — out of current file scope but should be an explicit skip+diagnostic.
- **[High]** Cross-module resolution requires one `analyzeFiles` batch over ALL project modules; parse-cache hits that skip the worker shrink the Program and degrade resolution of remaining files. The Roslyn worker has the same property for its semantic workspace, but for VB6 the ASG resolution is the primary value — the plan must define whether the worker receives the full .vbp file set (recommended) or only misses **[open design question]**.
- **[Medium]** `#If ... #End If` conditional compilation needs preprocessing or per-file error fallback (F1.7, issue #5).
- **[Medium]** ProLeap resolution had historical defects in WITH/member/ambiguity cases (issue #4 thread); golden fixtures must cover them.
- **[Medium]** `VbParserParams` default for `ignoreSyntaxErrors` unverified (F1.8); worker must test both and pick fail-soft with per-file error reporting.
- **[Low]** JDK 26 vs pom target 17: supported by javac, but confirm `mvn package` runs clean on the machine during the spike **[unverified]**.
- **[Unknown]** Whether `Module.getVersion()`/`isModuleWithMetaData()` expose anything the harness needs — not investigated.
- **[Unknown]** Rubberduck fork vitality/fixes not investigated (F1.7 #17).
- **[Inferred]** VB6 unqualified-name resolution ordering (F5.3) assembled from community sources, not a single spec.

## Recommended approaches (max 3)

1. **D2 Java worker per F2/F1 conventions**: vendored ProLeap (pinned commit, `mvn package`, build-lock cache), single `analyzeFiles` batch over the full .vbp module list with .frm/.ctl materialized as temp .cls inputs, Roslyn-identical JSON protocol + per-file regex fallback.
2. **Two-tier publication**: ASG-resolved calls → existing `calls_rows` path; everything else (ambiguous, late-bound, unresolved, name-heuristic) → POSSIBLE_CALLS with `{line, arity, resolution_status}` via `write_relations_typed` (Go precedent) and stable `site_id`s if per-callsite identity is needed; never `direct_resolved`.
3. **Fixture-first gate**: `tests/fixtures/vb6-application/` + `expected.json` golden tests + `benchmark_vb6_parse_quality.py` measuring parse-success ≥95% and resolution-rate before the engine is wired into `parse_vb_file`; bump `PARSE_CACHE_VERSION` in the same PR.
