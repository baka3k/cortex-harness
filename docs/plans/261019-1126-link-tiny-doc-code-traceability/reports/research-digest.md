## Findings

### 1. Doc graph node schema (Q1)

**Labels and properties written by `doc-tiny/graphrag_ingest_langextract.py`:**

- `Document` — merge key `{id}`; properties: `id` (= source_id), `name` (= source_id), `project_id`, `project_id_normalized`. Written at `doc-tiny/graphrag_ingest_langextract.py:421-424` (single) and `:559-562` (batch).
- `Paragraph` (NOT `Chunk`) — merge key `{source_id, paragraph_id}`; properties: `source_id`, `paragraph_id`, `text`, `short`, `project_id`, `project_id_normalized`, plus `SET p += $props` dynamic props (`:425-431`, `:563-569`). On LadybugDB the composite key becomes a synthetic `__pk` column (`"{source_id}::{paragraph_id}"`) — see `code-tiny/tools/graph/schema/ladybug_schema.py:263-277`.
- `Entity` — merge key `{id}`; properties: `id`, `name`, `type`, `name_norm`, `project_id`, `project_id_normalized` (`:444-459`, `:577-584`). Entity id is `uuid5(NAMESPACE_URL, "{project_id_normalized}::{type}::{name_norm}")` (`:200-212`); `name_norm` comes from `_normalize_entity_name(name, mode=...)` with default mode `"aggressive"` (`:267`).
- Edges: `(Document)-[:HAS_PARAGRAPH]->(Paragraph)` (`:431`), `(Paragraph)-[:HAS_ENTITY {confidence,start_char,end_char,surface,source_id,paragraph_id}]->(Entity)` (`:462-485`), `(Entity)-[:RELATED {type,source_id,paragraph_id}]->(Entity)` (`:486-502`).
- Index registry (`doc-tiny/graph_store.py:28-40`): `Chunk(doc_id,id)`, `Entity(name)`, `Entity(type)`, `Document(id)`. The `Chunk` label appears ONLY in this index list — no writer emits `Chunk` nodes today (grep across doc-tiny confirms); the ingest pipeline produces `Paragraph` nodes. Exact-name link queries must therefore target `Paragraph`/`Entity`, with `Chunk` treated as legacy/inferred-unused.

**Content hash per document: NO hash is persisted in the doc graph.** Document nodes carry only `id/name/project_id(_normalized)`. The only hash persisted doc-side is per-xlsx-row `row_hash` as a Paragraph prop (`graphrag_ingest_langextract.py:1228-1235`). Per-file SHA-256 for doc change detection lives OUTSIDE the graph, in the dev.py sync baseline:

- `cortex_harness/dev.py:1130-1136` `_doc_file_hash` (SHA-256), `:1198-1203` `_build_file_hashes` builds `{rel_path: sha256}`, saved via `_save_state` (`dev.py:908-912`) to `{project_dir}/.cortext-harness/sync-state/{md5(folder)[:12]}.json` (`dev.py:91` `SYNC_STATE_DIR = ".cortext-harness/sync-state"`, `:895-897` `_state_path`). Change detection priority git → hash → mtime: `dev.py:1149-1195`.

**Provider/store plumbing (reusable for link-tiny):** `doc-tiny/graph_store.py:19-22` inserts `code-tiny` into `sys.path` then imports `tools.graph.driver.{falkordb_driver,ladybug_driver}`; `create_graph_store_for_project(project_id)` (`:339-385`) resolves graph name via `project_contract.resolve_project_targets` and opens FalkorDBLite with `owner_id=os.getenv("CORTEX_STORAGE_OWNER","doc")` (`:283-290`, `:378-385`); default paths come from `resolve_storage(Path.cwd()).falkordb_doc_path` / `.ladybug_doc_path` (`:241-247`, `:279-282`).

- **StorageLease semantics** (`cortex_harness/storage/lease.py:19-94`): exclusive `portalocker LOCK_EX` per store file (`.{name}.cortex-owner.lock` beside the store, `:28-29`); non-blocking (`timeout=0`, `:46-48`); conflict raises `StorageLeaseConflictError` (`:15-16`, `:52-62`). ## Conventions to follow

1. **Registry-first project resolution** — every project-scoped operation calls `resolve_project_targets(project_id)` (`code-tiny/tools/common/project_registry.py:419`); naming contract `code_graph == project_id`, `doc_graph == f"{project_id}_doc"` (`:9-14`).
2. **Per-call `project_id`, no module-level state** — `fastmcp_server.py:210-213` and `project_contract.py:11-15` docstrings make this explicit; scope matching is casefold + prefix (`project_scope.py`, `project_registry.py:465-506`).
3. **v2 single-channel envelope on every tool result** — copy `doc-tiny/mcp_graph_rag.py:1372-1433` `_standard_tool` for a FastMCP facade; envelope keys and truncation behavior come only from `cortex_harness/mcp_contract.py`.
4. **Standalone-server argparse contract** — `--transport {stdio,sse,streamable-http} --host --port --path` with env defaults `FASTMCP_HOST/FASTMCP_PORT/FASTMCP_TRANSPORT/FASTMCP_STREAMABLE_HTTP_PATH` (`unified_mcp.py:3193-3216`, `mcp_graph_rag.py:1847-1866`); `stateless_http=True, json_response=True` for streamable-http (`unified_mcp.py:3271-3273`).
5. **Tree isolation with guarded delegation** — new tree imports code-tiny via `sys.path.insert` + `try/except Exception` fallback (`graph_store.py:19-22`, `project_contract.py:47-54`); never import `cortex_harness` from tree code at module import time (factory does the reverse lazily, `factory.py:438-440`).
6. **Read-only access to foreign stores** — lease at most one primary store; open the sibling via `additional_paths` (no lease) (`falkordb_driver.py:411-444`, pinned by `tests/test_mcp_sibling_no_lease.py`).
7. **Append-only artifact writes** — atomic tmp+`os.replace` everywhere (`incremental_sync_state.py:121-133`, `source_inventory.py:156-171`); locks via `portalocker` (`sync_scope.py:43`, `lease.py`).
8. **Lifecycle registration triple** — a new server needs: `MCP_SERVICES` entry (dev.py:196), lifecycle `SERVERS` entry + per-tree `mcp.sh` (mcp-lifecycle.py:68-81), and matching `--server` click.Choice (dev.py:2762); worker-stop support needs `_is_link_worker` + `SyncOwner` widening (sync_processes.py:14,72-92).
9. **Tests** — stdlib unittest or pytest with explicit sys.path injection; envelope assertions against `V2_KEYS` (`tests/test_mcp_output_contract.py:37`); no live-server dependency in unit tests.

## Risks / open questions

1. **`unknown`: where exactly should `links.jsonl`/`state.json` live under instance storage?** The instance root `~/.cortext-harness/v1/instances/{instance}/` currently contains only `qdrant/|falkordb/|ladybug/|manifest.json|backups` (`storage/config.py:445-477`, `layout.py:17-34`). No per-project artifacts directory exists yet; `layout.ensure_layout` + `manifest` validation (`layout.py:54-101`) would reject unknown owner entries if links were modeled as a third "owner". Likely safe: a new sibling dir (e.g. `instances/{instance}/links/{project_id}/`) that `ensure_layout` does not validate — but `unknown` whether the manifest drift check tolerates extra directories (needs a read of `layout.py:54-101` in full during planning).
2. **`inferred`: lifecycle env for a third server.** `mcp_runtime_config.runtime_environment` (`:204`) and `runtime_overrides` (`mcp-lifecycle.py:2334`) branch binary code/doc; `link-tiny` will silently get the "code" config section + code provider scoping unless these two functions grow an explicit link branch that overlays BOTH `FALKORDB_CODE_PATH` and `FALKORDB_DOC_PATH` (storage_overlay already emits both role paths regardless of owner — `config.py:498-503` — so a code-owner overlay may suffice, but graph-name selection at `:222-233` and `:251` sets only one `FALKORDB_GRAPH`; the link server should resolve both graphs through the registry at runtime instead of env).
3. **`inferred`: lease contention.** If link_mcp opens the doc store as primary (owner "doc") it will collide with the running doc MCP server's lease (`falkordb_driver.py:313-331`). The sibling-fan-out route (primary = one store, or no primary) is the safe design, but "open two stores with zero lease" is not exercised by any existing call site today (drivers always lease their primary) — may require a small driver extension or using a synthetic primary path. `unknown` whether FalkorDBLite/Ladybug tolerate two live readers in separate processes without lease when the writer rewrites the RDB — the fan-out docstring asserts snapshot atomicity (`falkordb_driver.py:419-426`) but only for the reader-in-writer-process case.
4. **`unknown`: doc-side stable per-document identity for links.** Document.id == source_id == relative path/spelling (`graphrag_ingest_langextract.py:433-434`), and two spellings exist (folder-mode relpath vs single-file stem — see the yake prune note `dev.py:1210-1226`). Links keyed on `source_id` must handle both spellings.
5. **`unknown`: `Chunk` label.** Indexed (`graph_store.py:29,36`) but never written; plan should target `Paragraph` and note `Chunk` as vestigial.
6. **`unknown`: exact-name link ambiguity.** `Entity.name_norm` is aggressively normalized (`graphrag_ingest_langextract.py:267`) while code `Function.name` is raw; a shared normalization helper does not exist across trees (inferred) — matching semantics need a decision in the plan.
7. **`--server link` collision risk:** lifecycle `startswith` matching means `--server l` or `--server link` matches `link-tiny`, but `--server all` would now start three servers and the port-uniqueness check (`mcp-lifecycle.py:2326-2328`) plus dev.py Choice update (`dev.py:2762`) must stay in sync (inferred, low risk).

## Recommended approaches

1. Model `link-tiny` as a sys.path tree (no packaging) with `registry_facade.py` copying `doc-tiny/project_contract.py:47-54` try/except delegation into `tools.common.project_registry`, and graph access via `doc-tiny/graph_store.py`-style drivers resolved from `resolve_storage(...)` + `resolve_project_targets(...)`.
2. Build `link_mcp` as a `doc-tiny/mcp_graph_rag.py` clone: `_standard_tool` envelope decorator + `FastMCP(MCP_NAME="link_mcp")` + argparse host/port(8790)/path, launched by a new `link-tiny/mcp.sh` and registered in `dev.py MCP_SERVICES`, `scripts/mcp-lifecycle.py SERVERS`, and `dev.py --server` Choice.
3. Run the linker under the existing `dev sync` guardrails: `@sync.group("link", invoke_without_command=True)` mirroring `sync_doc` (`dev.py:3750`), `_sync_lifecycle("link", ...)`, new `_is_link_worker` in `sync_processes.py`, reading changed-file sets from `.cache/incremental_sync_manifests/{scope_id}` + SHA truth from the inventory pointed to by `.cache/incremental_sync/*.json` (`inventory_path`), and doc-side SHA truth from `.cortext-harness/sync-state/*.json` `file_hashes`.
