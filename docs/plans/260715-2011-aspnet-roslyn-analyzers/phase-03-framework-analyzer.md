# Phase 03: Implement the ASP.NET Framework Analyzer

## Context

Combine compiler-backed C# evidence with Global.asax, System.Web pipeline types, App_Start/routing conventions, Web Forms markup/code-behind, web.config, resources, MVC/Web API, and views. Runtime execution and automatic source transformation are outside scope.

## Requirements

- Detect Framework modules without activating on unrelated C# projects.
- Reconstruct Global.asax events, `IHttpModule`, `IHttpHandler`, MVC/Web API routes/controllers/actions/filters, and Web Forms lifecycle/postback/state.
- Parse/redact the specified web.config sections and `.resx` resources.
- Preserve ordered pipeline/lifecycle behavior and markup/code-behind links.
- Emit unified labels/relationships, Framework metadata, and canonical C# anchors.

## Architecture

```text
detector -> project/module/artifact inventory
Roslyn -> System.Web types, overrides, attributes, calls, handlers
markup -> pages, controls, masters, directives, events, bindings
config/resources -> routes, modules, handlers, auth, state, settings
resolver -> effective request/lifecycle/view/config graph
pipeline -> deterministic result + dependency index
```

## Implementation Steps

1. Detect modules from target/project metadata, `System.Web`, `web.config`, Global.asax, App_Start, packages.config, and legacy markup.
2. Discover `.cs`, Global.asax/code-behind, `.aspx`, `.ascx`, `.master`, `.asmx`, `.ashx`, Razor views when present, `.config`, `.resx`, and project/package metadata.
3. Parse Global.asax events into `ApplicationEvent` facts and initialization/invocation evidence.
4. Extract module subscriptions/stages and handler mappings/`ProcessRequest`, async indicators, and request/response mutation evidence.
5. Extract MVC 2-5 and Web API 2 controllers, actions, routes, filters, binding, validation, results, redirects, and views.
6. Parse Web Forms pages, masters, controls, directives, code-behind/inherits, server controls, event handlers, ViewState, postback, and supported lifecycle stages.
7. Parse specified web.config sections/resources with inherited/local provenance and redaction.
8. Resolve routes, handlers/actions/pages, filters, views/layouts/partials, markup events, config consumers, and state/session writes.
9. Build project/config/code/markup/resource dependencies and selected/changed/deleted affected closure.
10. Add CLI dry-run/JSON/diagnostics, shared flags, failure policy, cache, and no-service imports.
11. Add golden tests for legacy request flow, Web Forms lifecycle/postback, MVC/Web API, malformed optional inputs, unresolved anchors, redaction, and determinism.

## Risks

- Dynamic subscription, reflection, custom build providers, and runtime routes may be unresolvable.
- Web Forms control trees/autogenerated fields can differ from source markup.
- Machine/site-level configuration inheritance may be absent from the checkout.

## Success Criteria

- The fixture traces endpoint mappings through application events/modules/handlers/controllers/pages to views/results with order and evidence.
- Page/control/master, lifecycle, ViewState/session, and postback facts are queryable without execution.
- Runtime-only behavior remains partial/unresolved and creates no fabricated resolved edges.
