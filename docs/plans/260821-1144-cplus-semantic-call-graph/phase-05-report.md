# Phase 05 Report: Pro*C source bundle, semantic bridge, and original-source mapping

Date: 2026-08-21 · Branch: `feature/local-db` · Status: complete (Phase 06 pending)

## Delivered components

### 1. Versioned source-map contract — `code-tiny/tools/cplus/proc_source_map.py` (new)

- `PROC_SOURCE_MAP_VERSION = "proc-source-map-v1"`, `MASK_POLICY_VERSION = "proc-mask-v2"`.
- Mapping-quality states: `exact_span`, `exact_line`, `line_directive`,
  `inferred`, `missing`, `stale`, `invalid`. Strict gate
  (`is_strict_map_quality`) accepts only `exact_span`;
  `ALLOW_EXACT_LINE_PROMOTION` is a policy flag defaulting to fail-closed.
- Two providers behind one contract:
  - **Sidecar manifest** (`parse_sidecar_map` / `load_sidecar_map`):
    hash-bound JSON entries; hash mismatch marks all entries `stale`;
    malformed structure/entries mark the map `invalid`; root containment
    enforced for file loading.
  - **`#line` directives** (`parse_line_directive_map`): region-based
    line-granularity mapping from Oracle-style `#line N "file"` markers.
    Never fabricates byte offsets (`original_start = -1`); foreign targets
    and missing directives are typed diagnostics.
- `ProcSourceMap.lookup()` returns typed `mapped | missing | conflict |
  stale | invalid` outcomes; overlapping disagreeing entries are
  `conflict`, never a name/proximity pick. Deterministic `fingerprint`
  and `quality_distribution` for cache/report integration.

### 2. Bundle lifecycle state machine

`classify_proc_bundle_state` derives `sql_only | lexical_ready |
semantic_eligible | semantic_complete | partial | stale | invalid |
failed`. Invalid/stale maps close the semantic lane before worker
outcomes; SQL facts survive every state. `bundle_state_allows_strict_calls`
admits only `semantic_complete`.

### 3. Reconciliation of generated semantic observations

`reconcile_proc_semantic_callsites` maps worker callsites (generated byte
coordinates) to original user-visible identity:

- original file/span/line is the identity; generated span/artifact stays
  provenance (`generated_*` fields);
- `refine_generated_class` combines worker classification with mapping
  provenance: mapped region + callee present in original source →
  `original_application`; mapped but absent → `unmapped_generated`;
  unmapped region keeps runtime/wrapper name-shape accounting;
- strict admission requires `original_application` + `direct_resolved` +
  strict map quality + accepted bundle/worker state, in that order;
  every other row keeps a typed `reject_reason`;
- per-reason accounting (`rejected`) makes generated runtime/wrapper
  traffic visible rather than silently dropped; `sql_facts_preserved` is
  asserted in every failure mode.

### 4. Versioned masking fingerprint wired into the parse cache

`cplus_analyzer` previously pinned `masking_fingerprint="proc-v1"`. Both
`ParseContext` construction sites now use
`proc_masking_fingerprint(source_sha256)`, which digests the mask-policy
version, the source-map contract version, and the source hash. Any mask
or map-contract version bump invalidates exactly the affected Pro*C parse
cache entries. `proc_manifest.py` now imports the shared version
constants (no duplicate version strings).

### 5. Scanner corrections coordinated with the Pro*C owner contract

The adversarial corpus exposed three violations of the owner's
length/newline-preserving mask invariant in `proc_analyzer.py`, all fixed:

1. **Indented `EXEC SQL` double-emitted leading whitespace** — the mask
   rolled back to the line start after the indentation was already
   emitted, growing the masked output (e.g. +2 bytes) and breaking all
   downstream offsets.
2. **Raw-string branch was unreachable** — `ch2 == "R" and
   source[i+1] == '"'` is self-contradictory; `EXEC SQL` inside raw
   strings was scanned as SQL.
3. **Raw-string end marker was wrong** — `)"' + delim` instead of
   `) + delim + '"`, so raw strings never terminated correctly.
4. **Multi-line `EXEC SQL` masks destroyed newlines** — the mask now
   preserves newline positions inside the masked span, keeping byte/line
   alignment for tree-sitter and enclosing-function joins.

## Coverage and gaps

- Worker protocol "2" already refuses raw `.pc`/`.pcc`, verifies artifact
  hashes, and rejects credential-bearing options (Phase 02/03); this phase
  adds the missing map/reconciliation layer and cache coupling.
- Vector embedding parity is unchanged: `_iter_vector_items` embeds only
  original-source `proc_nodes`; generated artifacts never enter payloads.
- Deferred to Phase 06: canonical schema/journal publication of the new
  staging rows and map records, and MCP exposure of bundle-state fields.
- Remaining known gap (owner-noted): `REFERENCES_STATEMENT` is declared
  but never emitted by the lexical scanner; unchanged here per ownership
  boundaries.

## Security posture

- Sidecar maps resolve only under an allowlisted root; escaping paths are
  rejected before parsing.
- No precompiler execution, raw command text, options, or credentials are
  persisted anywhere in the new module; fingerprints are digests only.
- Strict publication fails closed on every non-`exact_span` quality,
  non-application generated class, weak resolution class, and
  non-accepted bundle state.
