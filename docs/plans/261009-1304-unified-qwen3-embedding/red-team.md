# Red-team review — unified Qwen3-Embedding plan (261009-1304)

Reviewer lens: failure-modes (silent vector corruption, migration ordering, half-migrated states, missed call sites, device/pooling mismatches, rollback gaps, test gaps). All path:line claims below were verified against the repo on 2026-10-09. The plan's research digest is largely accurate; the defects below are mostly in **phase design**, not in the digest.

## Findings

### F1 — Critical: marker check is NOT on the default ingest paths; P3-before-P4 does not close blocker 2
P3 puts the sentinel check only in `primary_vector_sync.sync_vector_documents` (phase-03, change 1). But the **default** code ingest path for 12+ languages is the analyzers' own writer: `dev.py:1731` passes `--embed-model` to analyzer subprocesses, and the 12 CodeEmbedder analyzers upsert via their local `QdrantWriter` (e.g. `code-tiny/tools/python/python_analyzer.py:1708` `qdrant_writer.ensure_collection()`, `:1878-1885` `qdrant_writer.upsert(...)`), never touching `sync_vector_documents`. Also bypassing: `code-tiny/tools/cobol/qdrant.py:140-155` (cobol's own third sync path) and `code-tiny/livingdoc/living-doc-vectorize.py:226-229` + `living-doc-vectorize-infra.py:165-166`. After P4 flips the default, running `dev sync code` (or livingdoc vectorize) on a legacy jina collection upserts Qwen3 vectors into jina vectors with **zero errors** — the exact silent-mixing blocker (plan.md blocker 2) stays open on the majority of traffic.
**Fix:** enforce stamp+check in the shared write chokepoints — `local_qdrant.ensure_collection`/`LocalQdrantWriter.upsert` (skipping `{base}_mess` hash collections, which also go through `message_scan.py:447 writer.ensure_collection()`) and doc `create_collection` — instead of (or in addition to) `sync_vector_documents`; add it to cobol/qdrant.py and the livingdoc upsert paths.

### F2 — Critical: the P5 doc pilot reset cannot clear the doc-side marker → runbook deadlocks on its own step
P5's pilot uses `python doc-tiny/0_reset_all.py --project-id X --force` (phase-05 change 1). Per-project reset deletes points by filter `project_id_normalized` and **keeps the collection** (`doc-tiny/0_reset_all.py:57-72`). The sentinel payload is `{embedding_model, vector_size, stamped_at}` (phase-03 change 1) — no `project_id_normalized` field — so the stale `bge-m3` marker survives the reset, and the next Qwen3 ingest hits P3's hard error (AC2). The error tells the operator to run the same reset that doesn't work. Same trap for `reset_code_collection.py` if anyone ever scopes it by filter instead of drop. There is also no "marker present but collection empty → re-stamp" escape hatch.
**Fix:** make per-project reset also delete the sentinel point (or drop the whole `{project}_doc` collection, which is per-project by contract), and/or have the ingest check re-stamp when the collection holds only the sentinel.

### F3 — High: P1 keeps the AutoModel CPU fallback for an ST-backed model → silent garbage query vectors on accelerator failure
P1 change 2 says to keep the CPU fallback (`embed_runtime.py:249-265`) as-is. That fallback pops `_EMBEDDER_CACHE` and calls `get_embedder(model_name, "cpu")` — a **transformers AutoModel** — then `embed_query_with_model` mean-pools at `max_length=512` (`embed_runtime.py:183-198`). For Qwen3 (last-token pooling required), any MPS/CUDA runtime error during a query silently produces a mean-pooled garbage vector that is then stored in the query LRU (`_query_cache_put`), indistinguishable from good vectors. The fallback also evicts the wrong cache (ST models live in `_SENTENCE_TRANSFORMER_CACHE`, untouched by the pop at `:260-261`), and `get_sentence_transformer` (`:285-293`) has no load-time CPU failover at all. This contradicts P1's own AC4.
**Fix:** make the fallback ST-aware — evict/retry via `get_sentence_transformer(model, "cpu")` with the same `prompt_name`/`normalize_embeddings`; never route an ST-policy model through `get_embedder`.

### F4 — High: D2's doc-side query instruction is owned by NO phase; explore_service query path also missed
plan.md D2 (`plan.md:50`) commits to wrapping the doc query paths (`mcp_graph_rag.py:918,1019`, `graphrag_query_langextract.py:180`) with the Qwen3 query instruction. But P1 is explicitly code-side only ("không đụng doc-tiny (P4)" — phase-01 out-of-scope), and P4 changes only literals/env/device — no prompt. Result: doc queries are embedded bare; the model card says skipping the query instruct costs ~1-5% retrieval quality, which the P5 A/B gate may then misread as "model is worse". Additionally the code-side graph fan-out embedder `code-tiny/mcp/services/explore_service.py:184` does `_model.encode([text])[0].tolist()` — bare ST encode, no `prompt_name`, no `normalize_embeddings`, bypassing P1's policy entirely; no phase touches it.
**Fix:** assign doc-side query prompt (via `prompt_name="query"` with a missing-prompt fallback policy) and the `explore_service._make_embedder` encode to a phase (P1 or P4) with parity tests.

### F5 — High: no dependency floors; existing environments pass the pin but cannot load Qwen3
`requirements.txt:39` allows `transformers>=4.41,<4.56` and sentence-transformers is unpinned (`requirements.txt:15`, `doc-tiny/requirements.txt:13`). Qwen3-Embedding requires **transformers>=4.51.0** and **sentence-transformers>=2.7.0** (verified model card). Any env installed before the swap at transformers 4.41-4.50 (pin-satisfying) fails model load at first sync; ST <2.7 lacks `prompt_name` in `encode()` → TypeError at first query (D2 relies on `prompt_name` with no fallback or version guard). No phase touches requirements.txt — the digest raised this ("verify at implementation time") and the plan dropped it.
**Fix:** add to P4: bump `transformers>=4.51,<4.56` and pin `sentence-transformers>=2.7.0` in both requirement files; add a startup version check with an actionable error; document `prompt_name`-missing behavior (hard error, not silent).

### F6 — High: sweep misses real sites — both `.env.example` files, cobol's own sync path, and the AC2 gate trips on `ts_analyzer.py.bak`
- Root `.env.example` sets `CODE_EMBEDDING_MODEL=jinaai/jina-embeddings-v3` and `TEXT_EMBEDDING_MODEL=BAAI/bge-m3`; `code-tiny/.env.example` sets `CODE_EMBEDDING_MODEL=jinaai/jina-embeddings-v3`. Neither the digest F1 nor P4/P5 lists them; an operator copying the template silently re-pins jina forever (config/env beats the new default).
- P4 lists cobol among "8 delegating" analyzers via `sync_vector_documents` — false: `code-tiny/tools/cobol/cobol_analyzer.py:19` imports `tools.cobol.qdrant.sync_qdrant`, which has its own inline heuristic `"jina" in model_name.lower()` (`cobol/qdrant.py:129`) and its own `_delete_stale`/upsert (`:140-155`). P2's heuristic sweep and P3's marker both miss it (P2's AC2 grep pattern `_should_trust_remote_code|fix_mistral_regex` does not match this inline form).
- P2 AC2 gate `rg '_should_trust_remote_code|fix_mistral_regex' code-tiny/tools -l` matches `code-tiny/tools/ts/ts_analyzer.py.bak` (3 hits) — the gate as written can never go green or invites editing a backup file.
- D6's shared constant `code-tiny/tools/common/model_defaults.py`: doc-tiny is deliberately flat — `graphrag_query_langextract.py` and `embedding_utils.py` have no sys.path bridge to code-tiny (only `graphrag_ingest_langextract.py:26-31` has one, try/except with fallback), and `graphrag_ingest_langextract.py:1450-1451` documents that doc-tiny "does not have a Python package layout that can import from code-tiny". P4 doesn't say how 5 flat doc scripts import the constant; a copied fallback literal recreates the divergence D6 exists to kill.
**Fix:** add both `.env.example` files to the P4 sweep and P5 residual gate (`-g '!*.bak'`, plus a non-`.py` gate); add `cobol/qdrant.py` to P2; specify the doc-tiny import mechanism (bridge + single fallback constant) before craft.

### F7 — Medium: sentinel point-id namespace collides with real point ids, and the sentinel is searchable in unscoped queries
P3 uses `uuid5(NAMESPACE_URL, f"{collection}:embed-meta")`. Real point ids use the **same** `uuid.NAMESPACE_URL`: doc `_point_id` = `uuid5(NAMESPACE_URL, f"{pid}:{source}:{para}")` (`doc-tiny/graphrag_ingest_langextract.py:683`) and legacy code `_stable_point_id` = `uuid5(NAMESPACE_URL, symbol_id)` (`python_analyzer.py:1096-1097`). A symbol_id literally equal to `"{collection}:embed-meta"` (colons occur in namespaced symbols) makes the stamp overwrite a live point or a re-ingest overwrite the marker — marker silently lost, protection gone. Separately, unscoped queries suppress the project filter (`project_scope.py:141-153` returns `None`; `qdrant_query_support.search_collection:64-65`), so the sentinel's dummy vector can surface as a garbage hit in cross-collection merges.
**Fix:** use a dedicated private uuid5 namespace (pattern: `primary_vector_sync._POINT_NAMESPACE`, `primary_vector_sync.py:43`) and exclude the sentinel from search results (e.g. `must_not` on an `embedding_model` marker field, or store metadata outside the point space).

### F8 — Medium: query soft-warning wired only into fastmcp_server, but production default backend is cplus — and doc side has none
P3 change 3 adds the mismatch warning only to `code-tiny/mcp/fastmcp_server.py`. Production `semantic_search` traffic is dispatched by `unified_mcp` to one backend — **cplus by default** (`qdrant_query_support.py:4-6`), and all four backends keep byte-parallel `_qdrant_search` wrappers calling the shared helper (`cplus_mcp.py:935-949`, `android_mcp.py:754-768`, `java_mcp.py:603-617`, `fastmcp_server.py:683-698`). D4 promises query-side warning parity, and the doc-side query (`mcp_graph_rag.py:918,1019`) gets no warning at all. The "make half-migration visible" mitigation never fires in the default backend.
**Fix:** implement sentinel read + warning field inside `tools/common/qdrant_query_support.search_collection` (single chokepoint for all four backends) and in the doc query path; the per-process sentinel cache belongs there too.

### F9 — Medium: no backup before drop and no rollback procedure; A/B failure after fleet re-index is unrecoverable
The P5 runbook's pilot loop is drop-then-reingest with no `db_transfer export/import` backup step (the repo's own recommended backup, `code-tiny/scripts/rebuild_vector_collection.py:21-22`), and no revert procedure if the A/B gate fails — especially after "lặp cho mọi project" has re-embedded everything. Old jina/bge vectors are gone; rollback means full re-embed with the legacy model, whose post-swap health (trust_remote_code path, license download availability) is never re-verified by any test or runbook step.
**Fix:** add a mandatory pre-drop export step and an explicit rollback section (set `EMBEDDING_MODEL=jinaai/jina-embeddings-v3` / bge-m3 via env, reset, re-ingest, verify legacy parity test) to the P5 runbook; run the legacy-path test suite as part of the gate.

### F10 — Medium: P2 delegation regressions — `local_files_only` lost, D8 normalization not implemented on the legacy path, doc device env dead-end persists
- Today CodeEmbedder resolves a local snapshot via `resolve_embedding_cache` + `local_files_only` (`python_analyzer.py:950-963`), but `embed_runtime.get_sentence_transformer` (`embed_runtime.py:285-293`) has no `local_files_only` parameter. P2's "jina vẫn hành vi cũ" (AC1) is not achievable as specified — offline/no-network analyzer runs break or hit the network.
- `_embed_texts`'s ST branch calls `model.encode(batch, device=...)` with no `normalize_embeddings=True` (`python_analyzer.py:995-1004`); P2 never adds it, so D8 ("normalize cho Qwen3 cả ingest lẫn query", `plan.md:56`) is unimplemented for the 12-analyzer path (harmless for COSINE ranking but the stated invariant is false and any future dot-product consumer breaks).
- D7's "no more env dead-ends" misses one in its own AC3 chain: `dev.py` doc env sets `EMBED_DEVICE` (`dev.py:769-770`) while doc-tiny reads `EMBEDDING_DEVICE` (`doc-tiny/embedding_utils.py:31`) — `dev init` device selection never reaches doc scripts; P4's auto-detect (change 5) only helps direct script invocations.
**Fix:** extend `get_sentence_transformer` with `local_files_only` forwarding and thread `policy.normalize` into the legacy encode branch; wire `dev.py` doc env to `EMBEDDING_DEVICE` (or make doc-tiny read both).
