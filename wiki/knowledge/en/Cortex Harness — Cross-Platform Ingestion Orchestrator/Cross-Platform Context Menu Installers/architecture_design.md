The module is organized as a flat per-platform layout under `installers/` with one shared Python package and three independent installer pipelines:

- `common/config_manager.py` — the only cross-platform Python code. It defines `ContextMenuConfig`, auto-detects the project root (looking for `pyproject.toml` / `cortex_harness` markers), persists per-project settings in `.cortext-harness/context-menu.json`, and exposes a `click` CLI (`show`/`init`/`add`). Platform defaults (install paths, registry keys, script formats) are embedded in `_get_default_config`.
- `windows/` — two cooperating pieces: `registry_manager.py` wraps `winreg` + `ctypes.windll.shell32` to create/remove HKCR/HKCU context-menu trees (directory/background/drive) with optional UAC elevation via `ShellExecuteW runas`; `inno_setup/cortex_harness.iss` is an Inno Setup Pascal script that bundles the whole app, writes the same HKCR entries declaratively, sets `CORTEX_HARNESS_DIR`, and handles upgrade/uninstall logic.
- `macos/build_pkg.sh` — uses `pkgbuild` to assemble a `.pkg` from a temp staging tree containing `Library/Services/*.workflow` plus a `post-install.sh` that flushes `pbs`; intended to be invoked through the parent `dev installer build` command.
- `ubuntu/build_deb.sh` — uses `dpkg-deb` to build an `all` architecture `.deb` whose payload goes under `/usr/share/nautilus-scripts/CortexHarness` and whose `DEBIAN/postinst` restarts Nautilus; depends on `nautilus | gnome-terminal`.

Dependency direction is strictly downward: each platform package imports nothing from sibling platforms; only `common.config_manager` is reused across them. The shell scripts are standalone entry points (not imported by Python). The README documents the `dev installer {build,install,uninstall}` CLI surface exposed by the parent `cortex_harness/dev.py`.
