Two parallel entry points expose the same CLI surface (`build | install | uninstall | infra-up | infra-down | doctor | start | stop | help`): `mcp-lifecycle.py` for POSIX shells (invoked by `make` / the global `dev` wrapper) and `mcp-lifecycle.ps1` for Windows PowerShell. Both scripts share an identical data model — `SERVERS` and `INFRA_SERVICES` tuples describing code-tiny/doc-tiny MCP servers and qdrant/falkordb containers — so lifecycle operations are mirrored across platforms.

Shared runtime-environment resolution lives in `mcp_runtime_config.py`, which reads `.cortext-harness/config/*.json`, picks the active project, normalizes graph-provider selection (falkordb vs neo4j), derives `FALKORDB_*`/`NEO4J_*` aliases, and emits either JSON or a `format_bash_exports()`-formatted shell snippet; both lifecycle scripts import it to generate per-server `.active.env` files under `.cache/mcp/`. The Windows launcher additionally writes a `.active.json` and feeds it directly into the child process via `SetEnvironmentVariable`.

Process tracking is stateful: `start` writes PID records to `.cache/mcp/pids.json` and spawns each server in its own terminal window (macOS `osascript Terminal`, Linux `gnome-terminal`/`xterm`, Windows Git Bash or PowerShell); `stop` walks the saved PIDs plus scans the process table for command-line markers (`code-tiny/mcp.sh`, `doc-tiny/mcp.sh`, `mcp/unified_mcp.py`, `mcp_graph_rag.py`) and SIGTERMs them recursively by parent-child tree. `doctor` aggregates checks for Python venv, pip deps (`neo4j`, `falkordb`, `qdrant_client`, `requests`), Docker daemon, TCP ports, HTTP readiness, container existence, and MCP port reachability.

`validate_retrieval.py` is a standalone health-check tool that queries Qdrant collections and FalkorDB graphs for the active project, compares symbol linkage between vector points and graph nodes, counts modules/API endpoints, and compares the last indexed commit against `git HEAD`.
