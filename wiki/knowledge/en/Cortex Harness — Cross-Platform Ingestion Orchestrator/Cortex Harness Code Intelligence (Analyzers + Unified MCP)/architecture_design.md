Two concentric layers:

- `tools/<lang>/` primary analyzers (android, cobol, cplus, csharp, dart/flutter, delphi, go, java, js, kotlin, perl, php, plsql, python, rust, sql, swift, ts, vb*) each own one language's parsing pipeline and write graph facts plus Qdrant vectors; framework overlays (`spring`, `servlet_jsp`, `mybatis`, `struts`, `aspnet_core`, `aspnet_framework`, `flutter`) run after their seed parser and add graph-only framework semantics.
- `mcp/unified_mcp.py` is the single FastMCP entry point. It dynamically loads per-backend modules (`mcp/android/android_mcp.py`, `mcp/cplus/cplus_mcp.py`) via `_load_module`, maps every incoming tool call through `_dispatch_tool` / `_dispatch_planner_tool`, applies capability-driven default relationship types from `framework_registry.py`, and enriches responses with a `capability` / `query_engine` envelope.
- `tools/graph/core/factory.py` abstracts the graph backend behind `GraphDriverFactory.create_driver`, auto-switching Neo4j URIs whose scheme is `falkor|falkors|redis|rediss|unix` to `FalkorDBDriver`; `tools/graph/driver/{falkordb_driver,neo4j_driver}` implement the shared `GraphDriver` interface, while `tools/graph/operations/*` provide label-scoped CRUD helpers used by writers.
- Shared cross-language utilities live in `tools/common/` (call-graph builder, BM25 ranker, incremental sync state, message detectors, result packager) and are imported by both analyzers and MCP services.
- `scripts/` holds orchestration helpers (`incremental_sync.py`, `setup_graph_project.py`, `ingest_workflows.py`) invoked by the top-level `dev sync code` workflow; `testtool/` drives end-to-end MCP calls against JSON fixtures under `input_exam/`.
- Dependency direction: MCP → framework registry → backends → tools.graph.core → drivers; analyzers → common → graph core → drivers; no cross-analyzer imports except through `common`.
