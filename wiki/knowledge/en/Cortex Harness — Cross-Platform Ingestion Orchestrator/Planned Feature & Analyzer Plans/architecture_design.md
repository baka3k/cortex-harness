Each subdirectory is a self-contained plan for one feature or cross-cutting change, named `<YYYYMMDD>-<HHMM>-<slug>/`. Every plan follows a fixed shape: a top-level `plan.md` (YAML front-matter with `status`, `created`, `mode`, `scope`, `blockedBy`, `relatedPlans`) plus numbered `phase-NN-*.md` files describing sequential implementation steps; optional `reports/` and `research/` directories hold validation, red-team, and reference findings. Plans are not executable code — they are the coordination artifact between human reviewers and the automated planning skill (`hi-plan --fast/--full`). Cross-plan dependencies are declared explicitly in `relatedPlans` / `blockedBy` so that overlapping edits to shared registries (`incremental_sync.py`, `cortex_harness/dev.py`, `code-tiny/tools/graph/writer/language_writer.py`, unified MCP routing) can be coordinated additively rather than merged destructively. The plans collectively cover five families of work: (1) framework overlay parsers (Spring/Servlet/JSP/MyBatis, Flutter/Dart, Cobol, Perl, ASP.NET Roslyn), (2) MCP capability registry and query hardening, (3) primary vector ingestion completion, (4) incremental-scan reliability (locking, hybrid Git+SHA-256 detection, submodule topology, state migration), and (5) infrastructure migrations (Neo4j→FalkorDB, Makefile lifecycle).
