Flat collection of `test_*.py` files under `tests/`, each a self-contained `unittest.TestCase` (sync) or `unittest.IsolatedAsyncioTestCase` (async) module that imports production code from the sibling `code-tiny/` tree by prepending it to `sys.path`. Tests are grouped by concern: per-language analyzers (`test_cobol_*`, `test_aspnet_*`, `test_perl_*`, `test_flutter_*`, `test_dart_*`, `test_cplus_*`), framework overlays (`test_framework_*`, `test_struts_*`, `test_web_framework_overlay.py`), MCP acceptance contracts (`test_mcp_acceptance_matrix.py`, `test_unified_mcp_wrapper_signatures.py`, `test_unified_mcp_input_coercion.py`, `test_mcp_http_resilience.py`, `test_mcp_runtime_config.py`), incremental sync (`test_incremental_sync_*`), graph/vector backends (`test_falkordb_driver.py`, `test_qdrant_collection_scope.py`, `test_doc_graph_store.py`, `test_primary_vector_sync.py`), and dev CLI (`test_dev_lifecycle_commands.py`, `test_make_lifecycle.py`). Shared synthetic repositories live in `tests/fixtures/` (aspnet-core-application, aspnet-framework-application, database-schema-application, perl-application, web-framework-application) and are consumed via absolute `ROOT / "tests" / "fixtures" / ...` paths so tests run from any working directory. Async tests mock external drivers through `unittest.mock.patch` rather than spinning up real services.
